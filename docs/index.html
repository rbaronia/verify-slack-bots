IBM Verify Slack Bots

Two Cloudflare Workers that connect IBM Verify SaaS to Slack — real-time AI-classified security alerts with digest reports, and natural-language IAM queries through the /askiam slash command.

Cloudflare Workers IBM Verify SaaS Slack Gemini 3.5 Flash Lite MCP Streamable HTTP OAuth 2.0 PKCE
What's in this repo?

VerifyBot

Real-time IBM Verify audit event alerts posted to Slack with AI-powered severity scoring, plus automated daily, weekly, monthly, and quarterly digest reports.

  • Polls IBM Verify Events API every minute via Cloudflare cron
  • Receives instant push events via IBM Verify notification webhook
  • Gemini classifies each event — severity 0–10 with hard floors
  • Posts Block Kit alerts to #ibm-verify-alerts
  • Scheduled digest reports: daily, 7-day, 30-day, 90-day
  • /report slash command for on-demand reports

AskIAM

Natural-language IAM queries via the /askiam Slack slash command. Each Slack user authenticates with their own IBM Verify identity through OAuth 2.0 Authorization Code + PKCE.

  • Per-user OAuth 2.0 auth-code + PKCE flow — no shared credentials
  • Tokens cached in Cloudflare KV and auto-refreshed on 401
  • Gemini routes queries to IBM Verify MCP tools automatically
  • Admin ops: users, groups, apps, MFA, directory management
  • Self-service: access requests, approvals, my MFA enrollments
  • Paginated Block Kit results with Next Page / Show All buttons

Key capabilities
🔍

AI Classification

Gemini 3.5 Flash Lite scores every event 0–10 with deterministic severity floors for auth failures, MFA removal, and privilege escalation.

🔐

Per-User OAuth

Every Slack user completes their own IBM Verify PKCE flow. AskIAM never shares credentials — MCP calls run under the user's own identity.

📊

Digest Reports

Automated Gemini-written narrative summaries posted to Slack on daily, weekly, monthly, and quarterly schedules — or on demand with /report.

💬

Natural Language

Ask IAM questions in plain English. Gemini maps your query to the right IBM Verify MCP tool, calls it, and summarises the result — no syntax to learn.

Why two separate Workers?

The IBM Verify MCP server only accepts user Bearer tokens obtained through an OAuth Authorization Code flow — it rejects headless client_credentials tokens. This forces a clean separation:

🔔 VerifyBot — headless

Uses client_credentials to call the IBM Verify Events API on a schedule. Cannot call the MCP server. No user interaction required — runs entirely via cron and webhook.

🤖 AskIAM — per-user identity

Runs a real auth-code + PKCE flow for each Slack user. Caches tokens in KV. Calls the MCP server on the user's behalf — full identity context on every request.

Quick start

🔔 VerifyBot

cd worker-verifybot
npm install
npx wrangler secret put EVENTS_CLIENT_ID
npx wrangler secret put EVENTS_CLIENT_SECRET
npx wrangler secret put VERIFY_WEBHOOK_SECRET
npx wrangler secret put GEMINI_API_KEY
npx wrangler secret put SLACK_SIGNING_SECRET
npx wrangler secret put SLACK_ALERT_WEBHOOK_URL
npx wrangler secret put SEVERITY_THRESHOLD
npx wrangler deploy

🤖 AskIAM

cd worker-askiam
npm install
# First time only — paste ID into wrangler.toml
npx wrangler kv namespace create ASKIAM_TOKENS

npx wrangler secret put VERIFY_CLIENT_ID
npx wrangler secret put VERIFY_CLIENT_SECRET
npx wrangler secret put SLACK_SIGNING_SECRET
npx wrangler secret put GEMINI_API_KEY
npx wrangler secret put WORKER_BASE_URL
npx wrangler secret put CF_ACCESS_CLIENT_ID
npx wrangler secret put CF_ACCESS_CLIENT_SECRET
npx wrangler deploy
