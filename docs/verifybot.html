🔔 VerifyBot

A Cloudflare Worker that streams IBM Verify SaaS audit events into Slack with AI-powered severity classification, scheduled digest reports, and an on-demand /report slash command.

Live URL: verify-bot.baronia.workers.dev Slack channel: #ibm-verify-alerts Tenant: baronia.verify.ibm.com

Architecture

IBM Verify SaaS
  ├── Notification Webhook (push)  →  POST /verify-webhook  ─┐
  │                                                           ├── Gemini classify → Slack alert
  └── Events API (cron poll)       →  scheduled * * * * *  ──┘

Slack
  ├── /report [days]  →  POST /slack/command  →  button panel or instant report
  └── Button clicks   →  POST /slack/actions  →  period summary → Slack webhook

Cron (Cloudflare Triggers)
  ├── * * * * *      →  every minute: poll Events API for real-time alerts
  ├── 0 0 * * *      →  08:00 SGT daily digest (24-hour)
  ├── 0 0 * * 1      →  08:00 SGT Monday — 7-day weekly report
  ├── 0 0 1 * *      →  08:00 SGT 1st of month — 30-day report
  └── 0 0 1 */3 *    →  08:00 SGT quarterly (Jan/Apr/Jul/Oct) — 90-day report

How It Works

Real-time alerts

Every minute the cron trigger fires handleScheduled(), which calls the IBM Verify Events API for events since the last poll timestamp (stored in KV under lastPolledTime). Each event is sent to Gemini 3.5 Flash Lite for classification — Gemini assigns a severity score from 0 to 10 and a human-readable summary. Events at or above SEVERITY_THRESHOLD (default 6) are posted to Slack as Block Kit messages. Severity floors are also applied deterministically after Gemini (e.g. auth failures are always ≥ 7).

IBM Verify can also push events instantly via a notification webhook (POST /verify-webhook), which is authenticated with a shared secret in the X-Verify-Secret header. Webhook events go through the same Gemini classify → Slack alert pipeline.

Scheduled reports

Four additional cron triggers fire at 08:00 SGT (00:00 UTC) on different schedules to produce digest reports. Each fetches events for the relevant period, groups them by category, and asks Gemini to write a narrative paragraph with key statistics and top events. Reports are posted to the same Slack channel with a summary header.

/report slash command

Users can run /report or /report 30 in Slack to get an instant report. With no argument, a button panel is shown. Clicking a period button posts the report to the channel. Slack HMAC-SHA256 signature verification is enforced on every slash command and action request.

Deploy

cd worker-verifybot
npm install          # first time only
npx wrangler deploy  # deploys + registers all 5 cron triggers

To re-register crons after a wrangler.toml change, re-run npx wrangler deploy. Verify triggers with:

npx wrangler triggers list

Slack App Setup

  1. Go to api.slack.com/apps → Create New App → From an app manifest
  2. Paste slack-app-manifest.yaml (use JSON tab if YAML is rejected)
  3. Install to workspace → copy Signing Secret → push as SLACK_SIGNING_SECRET
  4. Copy Incoming Webhook URL → push as SLACK_ALERT_WEBHOOK_URL
  5. Left sidebar → Interactivity & Shortcuts → toggle On → set Request URL to:
    https://verify-bot.baronia.workers.dev/slack/actions

IBM Verify Webhook Setup

  1. baronia.verify.ibm.com → Admin Console → Security → Notification webhooks → Add
  2. URL: https://verify-bot.baronia.workers.dev/verify-webhook
  3. Authentication: Header → name: X-Verify-Secret → value: <VERIFY_WEBHOOK_SECRET>
  4. Event types to subscribe: Authentication, Management, SSO, Token, Access Request

Severity Classification

Gemini assigns a severity score from 0–10. After Gemini, deterministic floors are applied:

ConditionMinimum severity
Authentication failure7
MFA removal or deactivation8
Password reset or account deletion8
Impersonation or privilege escalation9

Only events at or above SEVERITY_THRESHOLD (default 6) trigger an immediate Slack alert. All events are included in digest reports regardless of severity.
