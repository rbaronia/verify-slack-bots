VerifyBot

Streams IBM Verify SaaS audit events into Slack with AI-powered severity scoring, real-time alerts, and automated daily / weekly / monthly / quarterly digest reports.

Architecture
IBM Verify SaaS

  │                                                           ├── Gemini classify → Slack alert
  └── Events API (cron poll)       →  scheduled * * * * *  ──┘

  ├── 0 0 * * *      →  08:00 SGT     — daily 24-hour digest
  ├── 0 0 * * 1      →  08:00 SGT Mon — 7-day weekly report

  └── 0 0 1 */3 *    →  08:00 SGT 1st Jan/Apr/Jul/Oct — 90-day quarterly report
How it works

Real-time alerts

Every minute the Cloudflare cron trigger fires handleScheduled(). It reads lastPolledTime from KV, calls the IBM Verify Events API for events since that timestamp, then updates lastPolledTime. Each event is forwarded to Gemini 3.5 Flash Lite for classification — Gemini assigns a severity score (0–10) and a human-readable summary. Events at or above SEVERITY_THRESHOLD (default 6) are posted to Slack as Block Kit messages with the severity score, category, and Gemini summary prominently shown. Deterministic severity floors are applied after Gemini.

IBM Verify push webhook

IBM Verify can also push events instantly via a notification webhook (POST /verify-webhook), authenticated with a shared secret in the X-Verify-Secret header. Webhook events skip the polling cycle and go straight through the Gemini classify → Slack alert pipeline.

Scheduled digest reports

Four cron triggers fire at 08:00 SGT to produce narrative digest reports. Each trigger fetches all events for the relevant period, groups them by category with counts, and asks Gemini to write a paragraph summary with key statistics, top event types, and security observations. Reports are posted to the Slack channel with a period header.

/report slash command

Users run /report in Slack for an on-demand report. With no argument a Block Kit button panel is shown — clicking a period fires the corresponding report into the channel. Slack HMAC-SHA256 signature verification is enforced on every slash command and Block Kit action request.

ℹ️ VerifyBot uses client_credentials — a headless flow that doesn't require any user login. This means it cannot call the IBM Verify MCP server, which only accepts user tokens. See AskIAM for the per-user query bot.

Deploy
cd worker-verifybot
npm install          # first time only
npx wrangler deploy  # deploys + registers all 5 cron triggers

To verify that cron triggers registered successfully:

npx wrangler triggers list

Re-running npx wrangler deploy after any wrangler.toml change is sufficient to update cron schedules.

Slack app setup
  1. Go to api.slack.com/apps → Create New App → From an app manifest
  2. Paste slack-app-manifest.yaml from this repo (use the JSON tab if YAML is rejected)
  3. Install the app to your workspace
  4. Copy the Signing Secret from Basic Information → push it as SLACK_SIGNING_SECRET
  5. Copy the Incoming Webhook URL → push it as SLACK_ALERT_WEBHOOK_URL
  6. Left sidebar → Interactivity & Shortcuts → toggle On → set Request URL to https://verify-bot.baronia.workers.dev/slack/actions
IBM Verify webhook setup
  1. Go to baronia.verify.ibm.com → Admin Console → Security → Notification webhooks → Add
  2. URL: https://verify-bot.baronia.workers.dev/verify-webhook
  3. Authentication: Header → name: X-Verify-Secret → value: your VERIFY_WEBHOOK_SECRET
  4. Event types: Authentication, Management, SSO, Token, Access Request
  5. Save and test with the IBM Verify built-in test button
Severity classification model

Gemini assigns a primary severity score from 0 to 10. After Gemini's response, the Worker applies deterministic floors — if Gemini scored too low for a high-risk event type, the floor overrides it:

ConditionMinimum severity
Authentication failure7
MFA removal or deactivation8
Password reset or account deletion8
Impersonation or privilege escalation9

Only events at or above SEVERITY_THRESHOLD (default 6) trigger an immediate real-time Slack alert. All events — regardless of severity — are included in digest reports.

Troubleshooting
SymptomFix
Button shows a warning triangleEnable Interactivity in Slack app settings and set the actions request URL (step 6 in Slack setup above)
Events API returns 403EVENTS_CLIENT_ID API client is missing Manage reports + Read reports entitlements in IBM Verify
No real-time alerts firingLower SEVERITY_THRESHOLD. Note: auth failures hard-floor at 7 and will always alert if threshold ≤ 7
getToken is not definedStale Worker version cached at the Cloudflare edge — re-run npx wrangler deploy
Cron triggers not firingRun npx wrangler deploy to re-register crons; verify with npx wrangler triggers list
Slack webhook 400 errorBlock Kit message exceeds Slack limits — run npx wrangler tail to inspect the payload
Missing events in reportsCheck lastPolledTime in KV — if it drifted far into the future, delete the key to reset
